# Open Questions

These questions remain open by design.

## Navigation

- Should the workspace appear as a Hubzilla app?
- Should it appear as a channel menu item?
- Should it be pinned by default for participating channels?
- What is the best user-facing name?

## PDL / Comanche

- What is the smallest valid blank PDL page for the workspace?
- Which Hubzilla template should be used first?
- Which regions should be reserved for guidance, status, and the runtime container?
- Should the PDL shell be generic or channel-specific?

## Runtime

- What is the minimum JSON definition structure?
- How does the runtime select which JSON definition to load?
- How are JSON definitions installed, enabled, disabled, exported, and restored?
- What local storage path is appropriate for JSON record files?
- What permission checks are needed before a JSON definition is loaded?

## Future API mode

- What API contract should be added later?
- How does the runtime represent API-capable JSON definitions?
- How are processing-node errors displayed?
- How are audit logs produced?

## Civic Infrastructure use

- How will Civic Infrastructure JSON definitions express Attestation, Affordance, and Affected-Status claims?
- How will CURRENT_RESIDENCE gained through SASE be represented to the runtime?
- What extra audit requirements apply to Civic Infrastructure JSON definitions?
